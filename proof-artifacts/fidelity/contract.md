# Representation Fidelity — Artifact Contract (G1 Row 2)

**Schema version:** `conduitscore.report_card.v1` + `AIVS-Micro` proof (`ed25519`)  
**Product:** ConduitScore (https://conduitscore.com)  
**Outreach hook name:** Representation Fidelity Check  
**Effective:** 2026-06-03  

---

## 1. Purpose

Prospects receive a **signed, shareable audit** showing how well AI systems can see and represent their website, plus a **cryptographic verify link** so the report is not “just a screenshot.” Cold email uses the **readiness score** as the hook; fulfillment delivers the full report card.

---

## 2. Inputs

| Field | Required | Description |
|-------|----------|-------------|
| `url` | Yes | Prospect website URL (`https://` added if missing). SSRF-safe public hosts only. |
| `scanId` | No | Reuse an existing scan when regenerating a report card. |
| API auth | For automation | `x-api-key` header on `POST /api/scan` (Pro+ REST API tier). |

**Outreach pipeline input:** domain or full URL → normalized → `POST https://conduitscore.com/api/scan`.

---

## 3. Outputs (what the buyer gets)

### 3.1 Scan result (API / outreach cache)

| Field | Type | Description |
|-------|------|-------------|
| `id` | UUID | Scan identifier |
| `overallScore` | 0–100 | AI readiness score (email hook) |
| `issues[]` | list | Top findings (title, severity, impact) |
| `fixes[]` | list | Remediation snippets (tier-gated) |
| `proof` | `AivsMicroProof` | Ed25519-signed micro-attestation of scan payload |
| `metadata` | object | Scanner version, timing, tier gates |

### 3.2 Representation Fidelity Report Card (`conduitscore.report_card.v1`)

Delivered at **`/reports/{scanId}`** (HTML) and buildable as JSON via `buildReportCard()`:

| Section | Content |
|---------|---------|
| `readiness_score` | Same as `overallScore` |
| `core_findings` | Up to 5 issues in plain English |
| `top_false_or_missing_ai_claims` | 2 AI-engine gap summaries (ChatGPT / Perplexity style) |
| `verification.verify_url` | `https://conduitscore.com/verify/{scanId}` |
| `verification.public_key_url` | `https://conduitscore.com/.well-known/aivs-public-key` |
| `verification.aivs_micro` | Signed proof object |
| `badge` | Embeddable SVG + HTML snippet |

### 3.3 AIVS-Micro proof (signature)

```json
{
  "url": "https://example.com",
  "dom_hash": "sha256:<64-hex>",
  "timestamp": "ISO-8601",
  "signature": "ed25519:<base64>",
  "scanner_version_hash": "sha256:<64-hex>",
  "scan_origin": "scan_result | html | visibility_probe"
}
```

**Verify:** `GET /api/verify/{scanId}` → `{ verification: { status: "valid" | "invalid" | "no_key" }, proof, canonicalPayload }`.

### 3.4 Formats

| Format | URL / path | Use |
|--------|------------|-----|
| JSON | `POST /api/scan` response; report card object | Outreach render, Cato tools |
| HTML | `/reports/{scanId}` | Prospect-facing page |
| Verify JSON | `/api/verify/{scanId}` | Third-party signature check |
| PDF | Not shipped in MVP | Future tier |
