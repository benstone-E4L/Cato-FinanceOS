## What ralph will build

Turn Cato from a RED-gated, plaintext-secret local daemon into a hygiene-clean, vault-secured
operator surface with vault-grounded Ask-E4L chat and a FinanceOS-aware Work Inbox as its default
landing page — strictly within the Cato repo, leaving Genesis, FinanceOS, and the Coordination
Ledger to parallel workstreams.

Chunks (6 total):
- CHUNK_1_HYGIENE: Clean up Cato's repo-hygiene debt (CI branch scope, dead code, unused
  dependency, WhatsApp duplication) before any other chunk lands on main.
- CHUNK_2_VAULT: Stand up Cato's encrypted credential vault and prove the daemon makes one live,
  correctly-routed model call using it.
- CHUNK_3_VAULT_INDEX: Index the E4L vault into Cato's existing memory engine per the Retrieval
  Contract's canonical chunk ID and metadata rules.
- CHUNK_4_ASK_E4L: Wire Ask-E4L chat to the Retrieval Contract (citations, contradiction
  surfacing, refusal path) and pass the 10-question Phoenix eval bar.
- CHUNK_5_FINANCE_VIEW: Add a read-only Finance nav view in Cato that consumes FinanceOS's
  control-room API and degrades to a stale-marked state without crashing when it's unavailable.
- CHUNK_6_WORK_INBOX: Make Work Inbox Cato's default landing page and reorganize the 23-view
  sidebar into the master spec's 9-item nav.

## When ralph gets stuck

1. Check `.ralph/errors.log` for the failure pattern.
2. Add a guardrail to `.ralph/guardrails.md` so ralph avoids the same pattern.
3. Fix the specific broken file manually if needed.
4. Update `.ralph/state.md` to point at the stuck task.
5. Restart the loop.

## Warnings from Spec Parsing

- Source material was two decision/audit documents, not a single spec-superstar-format spec — this
  workspace was hand-scaffolded (Phase 1 extraction done manually) rather than auto-parsed from
  headings.
- No `.env.example` existed in the Cato repo at scaffold time — create one from AGENTS.md's env
  var list before Chunk 2 runs.
- The exact 21-slug Genesis guarded-agent allowlist is NOT enumerated anywhere in the source audit
  — flagged as an open item in `.ralph/guardrails.md`. None of this workspace's 6 chunks currently
  dispatch a Genesis agent, so it does not block this workstream, but it must be resolved before
  any future chunk here (or in Phase E/F) adds one.
- Chunk 5's FinanceOS control-room integration depends on a capability-token mint endpoint that
  does not exist yet on FinanceOS's side (O2O-FOS-1) — Chunk 5's acceptance criteria were written
  to pass either way (live data OR stale-marked fallback), so this does not block the chunk, but
  full live-data proof is deferred until FinanceOS ships that endpoint.
- Chunk 1's "CI fires on a real push to main" acceptance criterion may not be provable inside this
  environment if push access to `main` isn't available here — documented as an acceptable manual
  follow-up rather than a fabricated proof.
